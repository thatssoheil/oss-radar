# 83213 - [Bug] Background process notifications delivered to wrong session after /new

- URL: https://github.com/NousResearch/hermes-agent/issues/83213
- Added: 2026-08-11

## Why claimable

P1 routing bug. `terminal(background=True, notify_on_complete=True)` completion
events carry only `session_key` (no platform/chat_id); queue-drain path
`_build_process_event_source` (run.py:22435) can route to the wrong session
after `/new`. Claimed after full RCA.

## Status

- 2026-08-11: claimed
- 2026-08-11: RCA complete - issue's proposed fix (honor stamped session_key) is INSUFFICIENT: `reset_session` (/new) keeps the same session_key and rotates only session_id (gateway/session.py:3199), so key-level routing can't discriminate origin from current on chat-keyed platforms. Real discriminator is `origin_ui_session_id` (already used by drain_notifications/async-delegation), which the terminal watcher never captures.
- 2026-08-11: withdrawn - posted full RCA on the issue for maintainers; no fix built (premise of the proposed fix unverifiable without reporter's state.db forensics)
