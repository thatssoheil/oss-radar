## Status

- 2026-08-11: withdrawn with E2E evidence - premise fails on current main: every write goes through Starlette Response.set_cookie -> stdlib http.cookies.SimpleCookie, which ESCAPES ';' as \073 (RFC 6265 octal escaping) in the Set-Cookie header; browsers decode on store and quote on re-send; Starlette's request.cookies parses the full payload back (verified round-trip intact: True). next= is URL-encoded before embedding so no value segment can smuggle a literal ';'. The issue is analysis-only (no repro), same AI-triage shape as #83784. A URL-encode fix would change a working path with a mismatch risk.
